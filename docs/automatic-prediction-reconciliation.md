# 全開催共通の予想保存・再照合キュー（3.49.43）

対象はJRA全開催場・全R。特定レース名・ユーザー印で分岐しない。

旧処理ではINSERT成功後に独立読返しが失敗すると、保存行の存在だけで次回の予想キューから
除外され、receiptのsaved記録がないまま再照合されなかった。

新処理は次の2種類を1回1Rのキューから選ぶ。

- 未来の未保存レース: 従来の正式カード・過去走・発走5分前チェックを通して評価/保存する。
- 保存行あり、receiptのsaved記録なし: 読取りによるハッシュ・保存時刻証跡の再照合のみ。
  発走後でも書き直し・再生成しない。成功した場合だけreceiptをsavedへ進める。

不確定書込の直後は例外を返し、同じ実行内で再送しない。次回実行が既存行を再照合する。
不一致はdeferredとして1時間の待機を残し、他の対象へ進む。保存済みを全件再監査しない。
確認済みreceiptは以降の予想キューから除外する。

再照合の自動選択範囲は今日から過去7日まで。未来は従来どおり7日先まで。
7日を過ぎた未確認記録は削除しないが、この自動キューの選択範囲外になるため個別対応が必要。
1回の選択はLIMIT1。D1 rows_readの本番削減値・消費量は未実測。
既存のscheduled読取予算・上限停止を通し、新たな外部取得/cronは追加しない。

ローカルSQLiteで、INSERT後の読返し失敗→同日発走後/翌日の再照合→saved記録→再処理なし、
破損データの再生成拒否とcooldown、東京/京都/新潟3会場の保存・独立読返しを検証する。
これは合成データであり、本番保存件数ではない。
