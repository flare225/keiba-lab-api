# 共通キュー入口と古い保存予想の回収（3.49.44〜45）

## 開催日・番組の入口

既存の番組行から対象日を作らず、JSTの当日〜7日先の8日を回収キューへ冪等登録する。
土日の決め打ちはせず、平日・祝日も日付候補としてJRA公式日別番組ページを確認する。
日付候補の存在は開催の証明ではない。HTTP失敗・空ページ・parse失敗はsource-unconfirmedで保持し、
開催なしとは判定しない。観測できた番組だけを保存する。ページに載らない開催場の存在は推測しない。

historyレーン内で最大1時間1日付/1外部ページを処理し、既存のJRA共有lease/cooldownを通す。
他のarchive/resultsレーンの公平な選択は維持する。次のhistory実行は回収時刻未到来なら通常処理へ進む。
403/429/503は既存共有取得枠を1時間休止し、他対象もその保護条件には従う。

公式ページの観測番組・出典・HTMLハッシュをreceiptへ先に保存する。
24時間以内の有効receiptを再利用して、番組の不足行だけをINSERTする。
program_key競合はDO NOTHINGで、既存番組・ユーザー印・LOCKを上書きしない。
独立SELECTで全キー/時刻と新規挿入行の各列を確認する。既存行との差異はエラーとして保持する。
INSERT後の読返し失敗はpending-readbackで残し、自動再送で重複行を増やさない。
観測各場12R未満はpartial-published-programとして再確認対象を維持する。
取得先エラーは次回時刻を残し、未試行の他日付を先に処理する。
D1日次上限は例外を上位budgetへ伝え、その後のcleanup SQLも行わずlease自然失効を待つ。

範囲外の過去開催日や8日以上先の番組欠落は、この入口の自動回収対象ではない。
過去番組は既存archive経路を使う。本実装で全期間の開催日収集が完了したとは扱わない。

## 8日以上前の未確認予想

既存hourly cronから、永続clockによって最大24時間1件だけ選ぶ。
日付インデックスと永続keyset cursorで候補メタデータを最大25行ずつ読む。
saved receiptや待機中を飛ばし、本文照合はそのうち1件だけ。確認済みの全過去予想を走査しない。
ページ末尾/処理した行までcursorを進め、失敗した同じ行が先頭を独占しない。末尾到達後は次回先頭へ巡回する。
readAutomaticPredictionだけで元のID/保存時刻/ハッシュと公式発走時刻証跡を照合する。
CAPTURE・INSERT・再生成・結果からの再構築は呼ばない。
成功はreconciled/saved receipt、失敗はdeferred+error/次回時刻、時刻未到来はold-recovery-not-dueで区別する。
未確認保存行は削除しない。1日1件という低頻度のため、多数あれば回収には日数が掛かる。
