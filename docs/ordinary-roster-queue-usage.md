## オフライン再生成

```sh
node scripts/prepare-ordinary-roster-queue.mjs docs/ordinary-roster-queue-2026-10-24.json
```

HTTP・DB・デプロイ処理はない。既存の同開催・同日の公開馬柱URLからrace IDの開催部分を取り、未補完枠のURL候補を作る。リンクを現物で確認したものではないため、`fetchAuthorized:false` / `publicationStatus:not-checked` を維持する。馬名・枠順・馬番・予想は生成しない。開催IDが矛盾する資料は拒否する。

## 取得再開の条件

`selectOrdinaryCandidate` は、ローカルに受け取った回復確認・共有ゲート・lease・receipt情報から候補を1件返すだけ。実行機能はなく、`execute:false` のまま。

- 回復確認またはゲート確認がない場合は候補を返さない。
- nextBatchAt / lockedUntil が未来の場合は停止。
- 独立した保存内容の読み返しまで完了したreceiptのみ `savedReadbackVerified:true` として除外する。POSTの成功表示だけでは除外しない。
- 次回試行が未来のreceiptは飛ばす。403/429/503や未確定書込を理由に即時再送しない。
- 実際の取得は既存 `missing-official-card-batch` の対象指定機能を使い、サーバー側の最新receipt・共有ゲート・lease確認を必ず通す。この一覧から直接JRAへ取得する処理は作っていない。
- netkeibaの候補URLが公開・対象一致と確認できた場合は、取得済みページを再利用し、出典分離した既存の名簿/履歴保存経路へ渡す。今回はそのページ自体を確保したわけではない。
