## 10/20の振り返りだけでは防げなかった理由

当時すでに「工程を分ける」「実経路で再現」「新規と再読込を分ける」と記載していた。それでも、障害発生時にその規則を使って次の作業を変えず、通る合成テストや小さなPRを進捗の中心に置いた。文書を増やしたことでは是正済みとしない。

以後は、変更前に次の4点を内部作業記録へ残し、その判断に従って実装/取得/保存を進める。ユーザーへ毎回チェックリストを送る必要はない。

1. 最後の成功工程と最初の失敗工程、根拠となる対象/時刻/保存版。
2. 実証済み原因・仮説・欠けている証拠の区別。
3. 次の作業が、その失敗工程を直接解消/識別する理由。
4. 次回の本番成功判定、未解決なら移る工程、承認が必要な操作だけの境界。

同じ停止記録の反復確認は、新記録/変更/未解決の必要証拠がない限り行わない。ただし未完了対象の新しい自然cron結果は確認可能。403・quotaを回避して証拠を作らない。
